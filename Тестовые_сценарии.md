## Общая информация о тестировании

| Поле | Значение |
|------|----------|
| **Название проекта** | Marketplace (Демоэкзамен) |
| **Рабочая версия** | 1.0 |
| **Имя тестирующего** | _указать ФИО тестировщика_ |
| **Дата(ы) теста** | _указать дату проведения теста_ |

### Роли в системе

| Роль | RoleId | Описание |
|------|--------|----------|
| Администратор | 1 | Полный доступ: выбор товара, создание, изменение, удаление |
| Клиент | 3 | Просмотр каталога без панели администратора и без кнопок управления |
| Гость | — | Вход без авторизации («Войти как гость») |

## Роль: Администратор

### Тестовый пример №1

| Поле | Значение |
|------|----------|
| **Тестовый пример #** | 1 |
| **Приоритет тестирования** | Высокий |
| **Заголовок/название теста** | Выбор товара и редактирование через кнопку «Изменить» |
| **Краткое изложение теста** | Проверка, что администратор может выбрать товар кликом по карточке и открыть окно редактирования кнопкой «Изменить». |
| **Этапы теста** | 1. Запустить приложение Marketplace.<br>2. На окне авторизации ввести логин и пароль пользователя с ролью «Администратор» (RoleId = 1).<br>3. Нажать «Войти».<br>4. Убедиться, что открылось окно `ProductWindow` в развёрнутом виде на весь экран.<br>5. Убедиться, что видны кнопки «Изменить», «Удалить» и «Создать».<br>6. Кликнуть по карточке любого товара в списке.<br>7. Проверить, что карточка выделена синей рамкой.<br>8. Нажать кнопку «Изменить». |
| **Тестовые данные** | Логин и пароль учётной записи администратора из БД (например, пользователь с `RoleId = 1`). Любой существующий товар в каталоге. |
| **Ожидаемый результат** | После клика по карточке товар выделяется рамкой. По нажатию «Изменить» открывается окно `AddEditProductWindow` с заполненными данными выбранного товара. Окно `ProductWindow` закрывается. |
| **Фактический результат** | _заполняется при выполнении теста_ |
| **Статус** | _Не выполнен / Пройден / Не пройден_ |
| **Предварительное условие** | Приложение установлено и запускается. База данных доступна, в таблице `Product` есть хотя бы один товар. В таблице `Users` есть активный пользователь-администратор. |
| **Постусловие** | Открыто окно редактирования товара. Сессия администратора сохранена в `CurrentSession`. |
| **Примечания/комментарии** | Если товар не выбран, при нажатии «Изменить» должно появиться предупреждение: «Выберите продукт, нажав на его карточку.» |

### Тестовый пример №2

| Поле | Значение |
|------|----------|
| **Тестовый пример #** | 2 |
| **Приоритет тестирования** | Высокий |
| **Заголовок/название теста** | Выбор товара и удаление через кнопку «Удалить» |
| **Краткое изложение теста** | Проверка, что администратор может выбрать товар и удалить его с подтверждением. |
| **Этапы теста** | 1. Войти в систему под учётной записью администратора.<br>2. На `ProductWindow` выбрать товар кликом по карточке (появляется синяя рамка).<br>3. Запомнить наименование выбранного товара.<br>4. Нажать кнопку «Удалить».<br>5. В диалоге подтверждения нажать «Да».<br>6. Проверить сообщение об успешном удалении.<br>7. Убедиться, что удалённый товар отсутствует в списке. |
| **Тестовые данные** | Логин и пароль администратора. Тестовый товар, допускающий удаление (желательно без критичных связей в заказах или с известными связями в `ProductInOrder`). |
| **Ожидаемый результат** | Отображается диалог «Удалить продукт «…»?». После подтверждения показывается сообщение «Продукт успешно удалён!», товар исчезает из списка, выделение сбрасывается. |
| **Фактический результат** | _заполняется при выполнении теста_ |
| **Статус** | _Не выполнен / Пройден / Не пройден_ |
| **Предварительное условие** | Пользователь авторизован как администратор. В каталоге есть товар для удаления. |
| **Постусловие** | Запись товара удалена из БД. Список на `ProductWindow` обновлён. |
| **Примечания/комментарии** | При отказе в диалоге («Нет») товар должен остаться в списке. Без выбора карточки — предупреждение «Выберите продукт, нажав на его карточку.» |

## Роль: Клиент

### Тестовый пример №3

| Поле | Значение |
|------|----------|
| **Тестовый пример #** | 3 |
| **Приоритет тестирования** | Средний |
| **Заголовок/название теста** | Просмотр каталога товаров без панели администратора |
| **Краткое изложение теста** | Проверка, что клиент видит список товаров, но не имеет доступа к поиску, сортировке и фильтрации. |
| **Этапы теста** | 1. Запустить приложение.<br>2. Авторизоваться под учётной записью клиента (RoleId = 3).<br>3. Дождаться открытия `ProductWindow`.<br>4. Проверить отображение ФИО пользователя в правом верхнем углу.<br>5. Проверить наличие списка товаров.<br>6. Проверить видимость панели «Поиск / Сортировка / Фильтрация» (`AdminPanel`). |
| **Тестовые данные** | Логин и пароль пользователя с `RoleId = 3` из БД. |
| **Ожидаемый результат** | Окно открыто в развёрнутом виде. Список товаров отображается. Панель `AdminPanel` скрыта (`Visibility = Collapsed`). ФИО клиента отображается вместо «Гость». |
| **Фактический результат** | _заполняется при выполнении теста_ |
| **Статус** | _Не выполнен / Пройден / Не пройден_ |
| **Предварительное условие** | В БД есть пользователь-клиент и записи в таблице `Product`. |
| **Постусловие** | Клиент находится на `ProductWindow`, данные каталога загружены. |
| **Примечания/комментарии** | Клиент не должен видеть элементы управления каталогом, доступные администратору. |

| **Краткое изложение теста** | Проверка входа гостя в каталог товаров и корректного отображения интерфейса. |
| **Этапы теста** | 1. Запустить приложение.<br>2. На окне авторизации нажать «Войти как гость».<br>3. Дождаться открытия `ProductWindow`.<br>4. Проверить подпись пользователя в правом верхнем углу.<br>5. Проверить наличие списка товаров.<br>6. Проверить, что окно развёрнуто на весь экран. |

| **Примечания/комментарии** | Гость не проходит форму логина/пароля. |

## Расшифровка тестовых полей

| Поле | Описание |
|------|----------|
| **Название проекта** | Наименование тестируемого приложения или модуля. |
| **Рабочая версия** | Версия сборки, в которой проводится тестирование. |
| **Имя тестирующего** | ФИО или логин специалиста, выполняющего тест. |
| **Дата(ы) теста** | Дата или период проведения тестирования. |
| **Тестовый пример #** | Порядковый номер тестового сценария. |
| **Приоритет тестирования** | Важность теста: Низкий / Средний / Высокий. |
| **Заголовок/название теста** | Краткое название проверяемой функции. |
| **Краткое изложение теста** | Суть проверки в 1–2 предложениях. |
| **Этапы теста** | Пошаговые действия тестировщика. |
| **Тестовые данные** | Входные данные (логины, товары, файлы и т.д.). |
| **Ожидаемый результат** | Корректное поведение системы при успешном прохождении теста. |
| **Фактический результат** | Реальный результат после выполнения (заполняется при тестировании). |
| **Статус** | Итог: не выполнен / пройден / не пройден. |
| **Предварительное условие** | Что должно быть выполнено до начала теста. |
| **Постусловие** | Состояние системы после завершения теста. |
| **Примечания/комментарии** | Дополнительные пояснения, ограничения, ссылки на дефекты. |
